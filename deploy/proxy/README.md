# HTTPS/mTLS ingress

For the Debian development controller in this workspace, run `sudo deploy/proxy/setup-nginx.sh --host 192.168.160.200` from the repository root. The script installs NGINX, creates separate server-TLS and device-identity CAs without replacing existing CA files, creates a private proxy secret, configures the mTLS ingress on TCP 443, validates it with `nginx -t`, and updates `sdwan-controller/.env.local`. It preserves other environment settings and does not change firewall rules or restart the Next.js process. Restart Next.js after setup. Operator mutation requests are accepted for the configured public origin or the HTTPS host forwarded by this trusted NGINX, allowing access through another DNS name that resolves to the same proxy. In `next dev`, the configured origin is also accepted alongside the current direct or forwarded request origin, which supports local access by IP or hostname when `.env.local` contains a different public origin.

For an isolated development lab only, the same script also exposes TCP 80 for `/fabric/edge.sh`, signed release downloads, and `/api/agent/v1/enroll`; other HTTP paths return 404. The installer and enrollment route go through the trusted proxy boundary. Allow the private controller IP under **Settings → Insecure HTTP lab controllers**, then create a new device/token; its instructions use HTTP even when the dashboard itself is opened over HTTPS. The HTTP listener sends the one-use token and CSR in cleartext on the lab network. The enrolled agent uses HTTPS/mTLS for management requests on TCP 443, so the edge still needs to trust the server CA before its first heartbeat. Do not publish TCP 80 beyond the isolated lab. The device CA and server CA remain separate.

The generated lab server CA is served at `/fabric/server-ca.crt`. Setup writes its SHA-256 fingerprint to `CONTROLLER_AGENT_CA_SHA256`, which Devices includes in the one-command enrollment instructions. The signed installer fetches the certificate over HTTPS, validates the pin before trusting it, installs it in Debian's system CA store, and passes it to enrollment so the agent also persists the CA in its private identity file. Operators do not need a separate manual certificate-install step. The bootstrap fetch uses `curl --insecure`, but a mismatch against the controller-published pin aborts before enrollment or service changes. The server CA private key stays on the controller and is separate from the device identity CA signer.

The script refuses to replace unmanaged NGINX files, existing CA material, an occupied TCP 443 listener, or a server certificate that does not cover the requested host. It does not modify a host firewall; permit TCP 443 only from the trusted lab network.

The agent initiates every management request. Use nginx.conf.template with a real HTTPS server certificate, a dedicated device CA certificate and a private upstream. Verified TLS client serial + verification status are forwarded only on agent paths; the application also checks a shared proxy secret, certificate expiry and current device revocation for every request. Enrollment is the only agent path that does not require a client certificate. Its token travels in the JSON body, never the URL.

Render PUBLIC_HOST, CONTROLLER_UPSTREAM and PROXY_SECRET into a private configuration file. Use a random hex proxy secret of at least 32 characters; set the identical CONTROLLER_AGENT_PROXY_SECRET on Next.js. Do not commit the rendered file. Do not use an unprotected publicly accessible upstream. On one host, bind Next.js to loopback and run NGINX locally; containers must share a private network with only the TLS proxy published. Header secret protection is defense in depth, not permission to expose the raw upstream.

Configure CONTROLLER_ENROLLMENT_URL and CONTROLLER_AGENT_URL to the externally reachable HTTPS origin and CONTROLLER_PUBLIC_ORIGIN for operator CSRF protection. The proxy must overwrite X-Fabric-Proxy-Secret, X-Forwarded-Host and X-Forwarded-Proto on dashboard requests; the application trusts forwarded origin data only when the proxy secret matches and the forwarded scheme is HTTPS. Use a certificate trusted by the agent OS or explicitly supply --server-ca for a private server CA. Keep the server TLS CA and device identity CA purposes separate in production. init:device-ca creates a dedicated private signer for the MVP; production key custody/backup must be established before pilot.

Validate the rendered configuration with nginx -t. The isolated smoke test uses pinned image nginx@sha256:9bf97bd7714f5e24c1ccd545ecb9eb5435cb6d109c97cebb15e7e455e0239edb. It tests real Go enrollment, controller config/telemetry, missing client certificate, spoofed headers, direct bypass rejection and revocation on an existing keep-alive connection. This is a local Docker/Next test, not a Debian network or production deployment gate.

Request bodies are bounded, enrollment has rate limiting, access logging is disabled to avoid credentials in logs. Device CA private key stays on the signer host with mode 0600; agents hold their own key in private local state. Revocation is application-checked even while a TLS connection remains open.
