## M2 — Enrollment, trusted TLS boundary and read-only agent (management MVP delivered)
Implemented in `sdwan-controller/migrations/0002_device_identity.sql` and `0003_runtime_errors.sql`/`0004_diagnostic_developer.sql` (diagnostics additions), controller enrollment, device-auth, PKI, renewal, channel and telemetry services/routes, `deploy/proxy/`, `api/openapi.yaml`, and the shared Go agent under `sdwan-edge/`. The agent enrolls with a signed CSR, renews certificates, polls and stages checksummed typed desired revisions, acknowledges received/rejected, and reports heartbeat/interface telemetry. The specific files and actual verification are recorded in STATUS.md and the change log.
Define PKI issuance/rotation, trusted upstream authentication, separate enrollment TLS and agent mTLS ingress, certificate-to-node binding, redacted activation-link flow and rate limits. Agent generates private keys locally. Proxy strips incoming identity headers; direct Next.js access cannot impersonate agents. Application checks revocation on every agent request.
Acceptance: concurrent redemption has one winner; expired/replayed/revoked credentials and wrong device scope fail. Prove spoof/bypass rejection against actual proxy, certificate renewal, revoked keep-alive requests and heartbeat persistence. No networking changes yet. Rollback: stop lab agent, revoke test identity, disable enrollment ingress; never rotate existing operator credentials.

## M3 — Safe local apply and recovery
The management portions of desired revisions, operator publishing, agent desired-state/ack endpoints, typed staging and bounded/deduplicated telemetry are delivered in M2. M3 must build on these contracts; do not create duplicate revision APIs or assume the network helper/service already exists.
Implement a local apply journal, last-known-good state, watchdog, preflight, verification and narrowly scoped typed privileged operations. Multi-subsystem apply is staged and recoverable, not globally atomic. Controller disconnection alone must not undo healthy forwarding. First validate local recovery behavior before enabling real network changes.
Acceptance: invalid revisions, stale acknowledgements, concurrent apply, process kills, disk errors and absent controller tested; local recovery works before actual network changes. Rollback: local journal restores LKG; console recovery procedure required.

## M4 — Real WireGuard/FRR/nftables engine
Create `sdwan-edge/internal/network/{wireguard,frr,nftables}/` with focused Go tests; `lab/inventory.yaml`, `lab/README.md`, `lab/scripts/`, `lab/scenarios/`; network ADRs.
Proposed design pending lab validation: distinct WireGuard interfaces per adjacency; hubs AS65000 with inter-hub iBGP over WireGuard, branches AS65001/65002 with eBGP; reachable next-hop, explicit ingress/egress prefix lists, deterministic preferred hub, no ECMP. Management/underlay routes cannot recurse into overlay. Reject overlapping LANs. CGNAT uses outbound transport; subnet-router intersite traffic gets explicit return routes, not automatic SNAT. Gateway internet egress NAT requires explicit configuration. Manage owned nftables tables/chains without global flush.
Acceptance: validate syntax on actual Debian/package versions, then prove dual tunnels, permitted/denied advertisements, spoof rejection, default-deny policies, host-to-host access, NAT branch and one-NIC mode. Rollback: agent snapshot/LKG plus independent console and management path.

At milestone completion run relevant controller `npm test`, `npm run test:integration`, lint, typecheck and build; agent `go test ./...`, `go test -race ./...`, `go vet ./...`, and build. Record unavailable checks UNVERIFIED. The agent-channel smoke does not replace Debian, VM forwarding, failover or reboot validation. Validate real proxy/network syntax and use the lab runner only after it exists; never invent successful command results.

## Change management and execution
Read scoped AGENTS.md and git status before edits. Classify risk and identify affected files/tests/rollback. After every meaningful task, including failed edits, append exact results to `docs/change-logs/log_change_NNN.md`, then report status, files, UI/network impact, risks, rollback and next step. Rotate before append exceeds 512000 bytes; preserve history. Until a tested logger exists, serialize document appends with an exclusive lock. For future concurrent agents, assign distinct file ownership and use the same locked logger; test contention and rotation before claiming safety.
Execute sequentially after implementation approval. Routine reversible approved work proceeds autonomously. Stop for destructive operations, missing access/credentials, or consequential architecture changes. Unverified work is never complete.
